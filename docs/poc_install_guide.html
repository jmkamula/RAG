ArionComply — POC Install Guide

Fresh VM → running system · Ship 47 · 2026-07-27

One-command install for a customer POC. Fresh Ubuntu VM to a working ArionComply with a first tenant provisioned in ~10 minutes.

Companion: architecture brief · demo walkthrough · per-control anatomy example

Prerequisites

VM

  • Ubuntu 22.04 or 24.04 (LTS)
  • 4 vCPU / 8 GB RAM / 40 GB disk minimum. Comfortable at 8 vCPU / 16 GB / 100 GB.
  • Outbound HTTPS to api.openai.com, debian.neo4j.com, pypi.org, and github.com. No inbound port requirements beyond SSH.
  • Regular user with sudo. Don't run the installer as root.

Credentials you'll need at install time

  • A password of your choosing for the arioncomply Postgres role (schema owner)
  • A password of your choosing for the arioncomply_app Postgres role (RLS-scoped app user)
  • A password of your choosing for the neo4j user
  • An OpenAI API key (or leave blank if using Anthropic / a local model — configure post-install)

Install — three commands

git clone https://github.com/jmkamula/RAG.git /data/arioncomply
cd /data/arioncomply
bash deploy/install.sh

The installer prompts for the four passwords above (or reads them from env if you pass --yes for CI mode). Then it runs through nine stages with progress printed at each step:

StageWhat happens
1. System packages apt install postgresql-16 python3-pip curl lsof git
2. Neo4j Adds debian.neo4j.com apt repo, installs Neo4j 5, sets initial password.
3. Postgres bootstrap Creates roles arioncomply + arioncomply_app, databases arioncomply_compliance + arioncomply_sessions, installs pgcrypto + pg_trgm extensions.
4. Schema + seed Applies db/baseline/schema_baseline.sql (77 tables, 15 views, 75 RLS policies) + db/baseline/seed_curator_data.sql (9 standards, retention policies, RBAC role catalog).
5. Python dependencies pip install -r deploy/requirements.txt (289 packages).
6. .env file Copies deploy/.env.example to /data/arioncomply/.env (chmod 600) with the passwords + OpenAI key substituted in.
7. Chroma + systemd Creates /data/arioncomply/chroma_db, installs Chroma + API systemd units, enables + starts the Chroma service.
8. Neo4j graph load Runs enrichment/documents/load_to_neo4j.py. Loads all curated frameworks (ISO 27001 / 27701 / 27003/4/5 / GDPR) + role-model edges. ~1-2 minutes.
9. API startup Starts arioncomply-api.service, waits for /docs to respond 200.
Idempotent — safe to re-run. If Postgres roles already exist, their passwords are updated to what you supply. Existing schemas are left in place. Existing systemd units are re-copied but not restarted.

Provision your first tenant

Run create_tenant.py

cd /data/arioncomply
PYTHONPATH=. python3 scripts/dev/create_tenant.py \
    --name "Customer Corp" \
    --industry technology \
    --country GB \
    --cloud-only \
    --employee-count 200 \
    --admin-email admin@customer.example \
    --admin-name "Customer Admin"

Output includes an API key printed once — copy it immediately. The raw key is SHA-256 hashed before storage; no way to retrieve it later.

What the script provisions

  • One tenant row + one admin user
  • Enrollment in ISO 27001:2022 + GDPR:2016/679 by default (override with --frameworks ISO27001:2022 ISO27701:2019 GDPR:2016/679)
  • Baseline client_facts: GDPR controller with EU + UK subjects. The tenant tunes this via the Profile UI post-install.
  • Initial posture_controls rows — one per curated control in each enrolled framework, all set to 'Not assessed'. ~430 rows for the default enrollment.
  • One admin API key with scopes: chat, hitl, documents, posture.

Verify

Health check

# Postgres + roles
sudo -u postgres psql -tAc "\l" | grep arion

# Neo4j
curl -s -o /dev/null -w "neo4j:  %{http_code}\n" http://127.0.0.1:7474/

# Chroma
curl -s -o /dev/null -w "chroma: %{http_code}\n" http://127.0.0.1:8000/api/v2/heartbeat

# API
curl -s -o /dev/null -w "api:    %{http_code}\n" http://127.0.0.1:8080/docs

All four should return 200. If any returns nothing, check journalctl -u arioncomply-{api,chroma}.

End-to-end test with the API key

KEY=arion_...  # the key create_tenant printed

# Dashboard posture — should show all-zero counts (fresh tenant)
curl -s -H "X-API-Key: $KEY" http://127.0.0.1:8080/api/v1/dashboard/posture | \
    python3 -m json.tool | head -30

# Sanity chat query
curl -s -X POST -H "X-API-Key: $KEY" \
     -H "Content-Type: application/json" \
     -d '{"question":"what is our posture on ISO 27001?"}' \
     http://127.0.0.1:8080/api/v1/chat | python3 -m json.tool | head

Access the UI

SSH tunnel from your workstation

ssh -L 8080:127.0.0.1:8080 -i ~/.ssh/your-key <user>@<vm-ip>

Then open http://localhost:8080/ in a browser. Set the API key in the top-right corner using the value from create_tenant.py.

Optional — observability stack

Trace every request end-to-end through Jaeger + Arize Phoenix.

sudo bash /data/arioncomply/ops/install_jaeger.sh

Then flip OTEL_ENABLED=1 in /data/arioncomply/.env and restart the API:

sudo systemctl restart arioncomply-api

Tunnel the UIs to your workstation:

ssh -L 16686:127.0.0.1:16686 -L 6006:127.0.0.1:6006 -L 8080:127.0.0.1:8080 \
    -i ~/.ssh/your-key <user>@<vm-ip>

Then:

  • http://localhost:16686/ — Jaeger (traces + service map)
  • http://localhost:6006/ — Phoenix (LLM prompt/completion viewer)
Privacy tier — OTEL_PRIVACY_LEVEL=debug puts prompt/completion content in the trace UIs. Use only when the VM is on an internal network. For production installs set OTEL_PRIVACY_LEVEL=observability (default) — paths + latencies + token counts only, no content.

Troubleshooting

SymptomFix
install.sh fails at step 4 with a syntax error in schema_baseline.sql Verify Postgres 16.x (not 15 or older) — the baseline uses PG-16 features. psql --version.
Neo4j graph load prints ClientError or blank output Wait ~30s more; Neo4j takes time to warm up on first boot. Re-run PYTHONPATH=/data/arioncomply python3 enrichment/documents/load_to_neo4j.py.
API returns 500 with RAG pipeline failed Chroma isn't up. Check sudo systemctl status arioncomply-chroma. Common cause: something else on :8000 (e.g. a Python http.server started by mistake).
Chat is 30 seconds cold First chat after startup rebuilds posture cache + engine overlay. Subsequent chats 4-8s. Fire a warm-up curl before demoing.
psycopg2.errors.InsufficientPrivilege: new row violates RLS policy when running admin scripts Scripts that INSERT into tenant-scoped tables must run as the arioncomply owner role, not arioncomply_app. create_tenant.py handles this via _admin_dsn(); pattern to follow for any custom scripts.
Firewall rules Only the SSH port needs to be reachable. All ArionComply services (:8080, :8000, :7474, :7687, :16686, :6006) bind 127.0.0.1. Access via SSH tunnel.

Uninstall / reset

Nuclear reset

sudo systemctl stop arioncomply-{api,chroma,jaeger,phoenix} 2>/dev/null
sudo systemctl disable arioncomply-{api,chroma,jaeger,phoenix} 2>/dev/null
sudo rm /etc/systemd/system/arioncomply-*.service /etc/systemd/system/arioncomply-*.timer
sudo systemctl daemon-reload

sudo -u postgres psql -c "DROP DATABASE IF EXISTS arioncomply_compliance;"
sudo -u postgres psql -c "DROP DATABASE IF EXISTS arioncomply_sessions;"
sudo -u postgres psql -c "DROP ROLE IF EXISTS arioncomply_app;"
sudo -u postgres psql -c "DROP ROLE IF EXISTS arioncomply;"

sudo systemctl stop neo4j
sudo apt-get purge -y neo4j
sudo rm -rf /var/lib/neo4j /etc/neo4j

sudo rm -rf /data/arioncomply

Then re-run bash deploy/install.sh for a clean slate.
