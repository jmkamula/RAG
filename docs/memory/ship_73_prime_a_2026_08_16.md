# Ship 73'.a — GDPR bridge-coverage gap audit

## Motivation

Task #595 (opened during Ship 68'.b dogfood) flagged 22 tenant-
facing GDPR articles without any ISO 27001 / 27701 bridge edge —
gaps in the framework-implementation-mapping catalog that Ship 68'.b's
"asserted implementation via related controls" UX made honestly
visible.

Ship 73' opens as the follow-on arc:
- **73'.a** — audit + triage (this ship)
- **73'.b** — author bridge edges for bridgeable articles
- **73'.c** — dogfood + arc close-out retro

## Method

`scripts/curation/audit_gdpr_bridge_gap_73a.py` walks every whole-
article GDPR node (Art.1 through Art.91), counts inbound ISO
bridge edges, and classifies each into one of four buckets:

- **already_bridged** — has ≥1 inbound ISO edge; no action.
- **tenant_facing_bridgeable** — no bridges but the article
  describes an organizational control that an ISO system could
  plausibly implement. Target of Ship 73'.b.
- **tenant_facing_unbridgeable** — the article describes a
  regulatory outcome (fines/penalties), a data-subject right of
  action (remedies), or a narrow context (church-affiliated
  organizations). Tenant-facing but no ISO control implements
  it — leaving unbridged is honest.
- **regulatory_internal** — supervisory authorities (Chapter VI),
  EDPB operational rules (Chapter VII), preamble/definitions
  (Chapter I). Not tenant-facing at all.

Per bridgeable article, the classifier draft-proposes the ISO
target(s) + edge type + confidence + rationale for Ship 73'.b to
refine and author.

## Sizing Ship 73'.b

14 articles / 22 proposed bridge edges. Comparable to Ship 69'.d
(12 stubs + 13 edges) in scale. Each edge proposed here has:
- Draft rationale (needs refinement for tone + specificity)

- Confidence assessment (guides the auditor)

Ship 73'.b will refine + author into `relationship_catalog.py`, run
the loader, verify posture_must_bridge_coverage picks up the new
edges on Arion.

## Codified lesson

### 46. Audit before curating — count what's there first

Task #595 was scoped as "22 unbridged articles." The audit revealed
the actual gap is 14 bridgeable + 7 legitimate carve-outs. Without
the audit we might have chased the 32 supervisory-authority articles
+ 4 preamble articles as bridge candidates, spent hours failing to
find plausible mappings, and either invented bad edges or given up
confused.

Reflection of Ship 69'.a's lesson (audit before refactoring; refactor
before schema-changing): the same principle for curator work. The
200-LOC classifier reduced the arc's scope decisively — before it,
73'.b was "22 articles to research"; after, it's "22 specific edges
to refine + author, most with confidence signal."

Rule: any curator arc that mentions a count of N items should start
with a script that verifies the count + classifies each into
actionable buckets.
