# Ship 71'.a — Expandable "N more" in Evidence Package

## Motivation

Ship 69's arc dogfood flagged as friction #2:

> **`…and N more asserted mappings` is a black hole.** No way to
> see which N. Auditor's next question ("show me all of them")
> isn't answerable in the EP surface.

The EP is served as a downloaded markdown file
(`/api/v1/dashboard/leaf/{id}/evidence-package`). No inline SPA
rendering, so any "expand" behavior has to live in the markdown
itself. HTML5 `<details>/<summary>` tags are valid inside
GitHub-flavored markdown, render as expandable in every
mainstream markdown viewer, and stay plain-text-legible in a raw
text editor. Right tool for a downloaded-artefact surface.

## The change

`rag/posture/evidence_package.py::_render_bridged_leaf` — the ↗
block used to emit:

```
  ↳ Asserted implementation via _A.7.2.6_ (IMPLEMENTS, confidence: HIGH)
    Rationale: ...
  ↳ Asserted implementation via _A.5.19_ (IMPLEMENTS, confidence: HIGH)
    Rationale: ...
  ↳ Asserted implementation via _A.5.20_ (IMPLEMENTS, confidence: HIGH)
    Rationale: ...
  ↳ …and 12 more asserted mappings.
```

now emits:

```
  ↳ Asserted implementation via _A.7.2.6_ (IMPLEMENTS, confidence: HIGH)
    Rationale: ...
  ↳ Asserted implementation via _A.5.19_ (IMPLEMENTS, confidence: HIGH)
    Rationale: ...
  ↳ Asserted implementation via _A.5.20_ (IMPLEMENTS, confidence: HIGH)
    Rationale: ...
  <details>
  <summary>Show 12 more asserted mappings</summary>

    ↳ _27701 B.8.5.4_ · IMPLEMENTS · confidence HIGH · NC 4/17 MUSTs satisfied
      Rationale: 27701 B.8.5.4 legally-binding request notification…
    ↳ _27701 B.8.2.2_ · IMPLEMENTS · confidence HIGH · NC 3/18 MUSTs satisfied
      Rationale: 27701 B.8.2.2 is the certifiable operationalisation…
    …

  </details>
```

Compact per-source shape inside the collapsed block:
`std ref · edge · confidence X · finding N/M MUSTs satisfied` on
one line, rationale on the next. No excerpts inside — the top-3
render already carried one excerpt per unique source ref (Ship 62'
dedup), so repeating them would be noise.

The remaining sources are sorted the same way as the top-3
(Ship 70'.a's `target_granularity DESC, n_source_musts DESC`), so
the auditor gets the same precision-first ordering when they
expand.

## Verified on Arion (Art.28:data_processing_agreement, Confidentiality MUST)

3 top-visible sources + 12 collapsed inside `<details>`. When
rendered in a browser or GitHub, the details block starts closed
with a clickable "Show 12 more asserted mappings" label. Every
one of the 15 curator-authored mappings is now reachable.

## Files touched

- `rag/posture/evidence_package.py` — 40 LOC (details/summary
  emission + compact per-source formatting + reuse of Ship 70'.a
  ranker for the remaining).
- `tests/test_evidence_package.py` — 3 new assertions locking the
  details block presence.

Zero schema. Zero SPA. Zero loader. The auditor gets an EP with
no black holes; markdown viewers get proper expand/collapse.

## Codified lesson

### 38. Match the medium

The Ship 71' options list started with "JSON API + SPA render"
because *"expandable"* triggers "we need a widget." But the EP
is delivered as a markdown attachment; the auditor's viewer is
whatever renderer they use. HTML5 within markdown covers 100% of
that surface with zero new infrastructure.

Rule: the shape of the fix follows the shape of the artefact.
Downloaded markdown → HTML-in-markdown. Inline SPA → SPA
widget. JSON consumer → JSON endpoint. Don't bring three-layer
solutions to a one-layer problem.
