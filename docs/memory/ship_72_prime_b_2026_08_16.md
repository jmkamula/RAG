# Ship 72'.b — LLM path routed through FindingContract

## What changed

Two extractor sites migrated to `FINDING_CONTRACT.bind()`:

1. **`_extract_templated_via_full_section`** (extractor.py:1201) —
   the legacy templated fallback path used when the doc has raw
   `<<MUST item:X>>` markers but no `<!-- EDIT-ZONE-START -->`
   comments and no `<!-- TABLE-COLUMNS -->` metadata. Missed from
   72'.a scope. Now routes through the contract; empty sections
   drop as `PURE_SCAFFOLDING` instead of emitting inert NC rows.
   Modern advisory + SSoT + Evidence Package surface missing evidence
   deterministically — no need for placeholder NC rows.

2. **`_parse_llm_response`** (extractor.py:2621) — the LLM-response
   parser that converts pass-1/pass-2 LLM output into `DocumentFinding`
   rows. Now flows through the contract with LLM-specific fields
   (`chunk_id`, pre-resolved `control_ref` + `standard_id`, custom
   `finding` value like NC/OFI/Comply, custom `confidence` value).
   All pre-existing LLM-side filters (`dropped_low_conf`,
   `dropped_short_quote`, `dropped_hallucinated`, `dropped_unbound`,
   etc.) preserved — they filter BEFORE the contract, so the contract
   is a second gate rather than a replacement.

## What FindingContract catches on the LLM path

Two failure modes the local filters miss:

- **LLM hallucinated MUST ids** — the LLM sometimes proposes a
  `checklist_item_id` that isn't in the per-control valid set. The
  per-control filter (extractor.py:2591-2594) catches these WHEN a
  valid set exists for that control. When the LLM proposes a
  `bound_item_id` and the local filter accepts it, the contract's
  broader `catalog_recognises` acts as a second gate.

- **LLM scaffolding pulls** — the LLM occasionally pulls
  "*Standard text: ...*" or "*Do not edit — system id*..." prose
  from our own template scaffolding as "evidence." The contract's
  `is_scaffolding` predicate catches these — the LLM's own filters
  wouldn't.

## Contract extensions

`ExtractedCandidate` gained three optional fields for LLM-path
plumbing:

- `chunk_id: Optional[str]` — LLM chunk provenance for tenant-facing
  observability.
- `control_ref: Optional[str]` — pre-resolved ref for extractors that
  didn't derive from `item_id` (LLM output, structured rows,
  fingerprints).
- `standard_id: Optional[str]` — same for standard.

The contract's `.bind()` prefers pre-resolved values when present
and falls back to deriving from `item_id` when not. Item-id
validation is skipped when the caller passes empty `item_id` (control-
level LLM findings without per-MUST binding are dropped by the LLM
path's own `bound_item_id is None` filter before they reach the
contract; sending them here would be a bug).

is orthogonal to the LLM path. Scheduled for a future sub-arc; not
72'.c (which is xlsx-focused) to keep each sub-ship tight.
