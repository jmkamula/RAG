# Ship 79'.a — DPIA + DQA regression scoping

Opens Ship 79'. Ship 78'.f flagged DPIA (-12.7pp) + DQA (-9.9pp)
F1 regressions vs single-path best under Ship 78's union+tuned
mode. Ship 79'.a investigates the root cause and locks the
direction.

## Audit findings

### The measurement

Per-doc F1 (lenient scoring, 5-doc aggregate):
- Consensus alone: 15.2%, DPIA 40.7%, DQA 27.9%
- Critic alone: 19.8%, DPIA 16.7%, DQA 38.5%
- Union + tuned (D): 23.6%, DPIA 28.0%, DQA 28.6%

Two docs where union+tuned lost ground: DPIA (-12.7pp vs
consensus-alone) + DQA (-9.9pp vs critic-alone).

### Investigation via `scripts/ship79a_regression_audit.py`

The audit isolated MUSTs unique to each variant + how union+tuned
handled them:

| Doc | Only consensus | Only critic | Both | Union added |
|-----|:-:|:-:|:-:|:-:|
| DPIA | 27 | 6 | 6 | **15** |
| DQA | 17 | 3 | 7 | **5** |

The 15 DPIA + 5 DQA "union-added" MUSTs — neither consensus nor
critic emitted them — all scored as "unknown" against ground
truth (i.e. not enumerated as satisfies / partial / not_satisfies
in the yamls).

Spot-check on 4 of them (via `scripts/ship79a_spotcheck.py` +
direct DB query):

| Finding | Excerpt (source) | Assessment |
|---------|------------------|------------|
| A.5.34:rev_dpia_review | DPIA intro | Wrong artefact (A.5.34 = privacy policy) |
| A.7.5.1:proc_documented_compliance | DPIA intro | Wrong artefact (A.7.5.1 = transfers) |
| Art.15:purposes | DPIA scope | Wrong artefact (Art.15 = right of access) |
| Art.32:reg_risk_assessment | DPIA intro | Debatable (DPIA has security risk assessment; but Art.32 primary artefact is a security policy) |

Verdict: **4 of 4 spot-checked are wrong-artefact false
positives**. The regression is REAL, not a GT-enumeration gap.

### Root cause

Ship 78'.c's tuned `_GATEKEEPER_SYSTEM` prompt says (paraphrased):

> Accept liberally — an auditor accepts touch-evidence and follows
> up if needed. Accept when the excerpt mentions the MUST's subject
> at all (even briefly).

On structured procedure docs (DPIA, DQA, RoPA), the doc's intro
and scope sections mention MANY topics (privacy, PII, data
subjects, security measures, etc.). Fingerprint keywords match
those mentions across many refs. The tuned LLM sees "does the
excerpt mention the topic?" and accepts.

But those mentions aren't evidence FOR those MUSTs — they're
evidence for the doc's PRIMARY artefact (Art.35 DPIA MUSTs, for
DPIA doc). The tuned LLM lost the "which artefact does this doc
BUILD?" discipline.

Prose-heavy docs (Consent, ProcOps) don't have this problem
because they lack the terse header/scope prose that triggers
cross-ref fingerprint hits.

## Direction (locked)

**Add artefact-awareness to `_GATEKEEPER_SYSTEM` prompt.**

Tune the prompt to enforce artefact discipline: an excerpt is
evidence for a MUST only if the excerpt is about the SAME
ARTEFACT that the MUST is on. Give examples specific to
common cases:
- DPIA proc excerpt ≠ evidence for privacy policy MUSTs
  (A.5.34's `pii_processing_register` / `privacy_and_pii_protection_policy`).
- DPIA proc excerpt ≠ evidence for Art.15 (right of access)
  unless the excerpt specifically discusses subject-access.
- RoPA proc excerpt = evidence for Art.30 register MUSTs AND
  for A.5.34's `pii_processing_register` (same artefact class,
  per Ship 77'.c revision).

Rationale over other options:
- (Option 2) Doc-shape signal for dedup would require
  identifying doc's primary artefact deterministically — complex
  + error-prone.
- (Option 3) Post-hoc artefact filter is deterministic but
  brittle: how do we enumerate "acceptable artefact class" per
  MUST without curator work?
- (Option 4) Combine: could over-engineer if prompt tune alone
  works.

Prompt tune is the smallest change with the highest leverage.
If it doesn't recover DPIA+DQA precision on measurement, escalate
to doc-shape signal.

Codified lesson candidate for 79'.e:

**"Touch-evidence" acceptance needs artefact bounds.**
Ship 78'.c's auditor-realistic prompt was right in principle
but too coarse-grained. Real auditors accept touch-evidence
FOR THE ARTEFACT THEY'RE READING. A DPIA proc reader accepts
touch-evidence for Art.35 MUSTs; they DON'T accept the same
excerpt as evidence for Art.15 (access rights) or A.5.34
(privacy policy). Artefact scope is implicit in the auditor's
mental model; the LLM prompt needs to make it explicit.
