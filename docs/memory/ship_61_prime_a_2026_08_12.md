# Ship 61'.a — Evidence Package hybrid (SSoT + raw findings)

## The arc in one sentence

Ship 61'.a closes the last SSoT reader migration deferral (task
#590) — `rag/posture/evidence_package.py` now uses
`posture_must_verdicts` for coverage counting + per-element state
(matching the Ship 60' advisory discipline) while keeping
`document_findings` as the source of verbatim excerpts the auditor
needs.

## Motivation

Evidence Package is the highest-stakes tenant-facing output — an
auditor-ready markdown summary that the tenant hands to their
external assessor. Pre-Ship-61'.a it counted an element as "covered"
if it had ≥1 approved `document_findings` row. Two problems:

1. **No SSoT parity.** Every other advisory surface (Dashboard
   advisory panel, drill-in, chat markdown, case-file card) uses
   SSoT via `read_must_verdicts_by_control`; Evidence Package
   diverged. An element could show ✓ here but ○ in the chat.
2. **No cross-framework attribution.** Ship 60' put a "covered via
   ISO 27001" nudge on four surfaces (advisory panel / drill-in /
   chat markdown / case-file card / digest). The auditor-facing
   surface, which most needs attribution provenance, had none.

## Design

**Hybrid split:**
- **Coverage counts + per-element state** — SSoT.
  `read_must_verdicts_by_control(pg, tenant, control_ref, standard_id)`
  returns the tenant's per-MUST verdicts (`.satisfied`, `.stale`,
  `.partial`, `.bridge_sources`). Ship 61'.a categorises each MUST
  as one of:
    - `direct`   — SSoT `.satisfied` is True.
    - `bridged`  — not satisfied direct BUT `.bridge_sources` non-empty.
    - `missing`  — no coverage of any kind.
  N/A-excluded MUSTs (per Ship 58's absence-of-row convention) drop
  from the leaf's required-elements list entirely — the auditor
  isn't asked to check something outside the tenant's scope.
- **Verbatim excerpts + document references** — `document_findings`.
  Unchanged. The auditor needs the source text as it appears in the
  tenant's uploaded document.
- **SSoT-empty fallback** — when `ssot_verdicts` is empty (fresh
  tenant, sweep lag, schema not applied), degrade to the pre-61'.a
  behavior: count via `findings_by_element.get(mid)` presence, no
  bridge attribution surfaced.

**Render additions:**
- Header: new `**Cross-framework coverage:** N elements are covered
  by evidence for related ISO 27001:2022, ISO 27701:2019 controls`
  line, silent when zero.
- Required-elements list: three markers instead of two.
    - `- ✓ **<text>**` — direct-satisfied. Verbatim excerpts +
      filename + section + confidence, unchanged.
    - `- ↗ **<text>** (cross-framework coverage)` — bridged. Top-3
      grouped bridge sources: `↳ Covered via _ISO 27001:2022 A.5.15_
      (IMPLEMENTS)` + tail count when >3.
    - `- ✗ **<text>**` — missing (unchanged).

**What stays deterministic:**
- No LLM. The whole package is a deterministic compose of SSoT +
  Postgres + Neo4j reads.
- Bridge source refs are curator-authored data (Ship 59'.b/e).
  Rendering them as attribution doesn't invent claims.
- Verbatim excerpts still come from the tenant's own documents.

## Design decisions

**1. SSoT for MUSTs, findings for SHOULDs.**
SSoT stores per-MUST verdicts only (Ship 58 design). Recommended
additions are `should_contain` items which aren't in SSoT. Ship
61'.a keeps them on the legacy `findings_by_element.get(sid)`
heuristic — semantically appropriate since SHOULDs aren't strict
requirements the engine tracks.

**2. Bridged elements suppress the "no evidence yet" text.**
Pre-61'.a, an unmet element unconditionally said "No evidence yet.
Add or upload a source that addresses this element." Ship 61'.a
distinguishes: if the tenant has related-framework evidence, we
say "cross-framework coverage" instead — an honest positive signal
that helps them plan (they may not need to author fresh artefacts
if they can extend their ISO docs' scope).

**3. Bridge display capped at top-3 groups.**
Art.32's `rev_iso_alignment` MUST has 107 bridge sources on the
Arion demo. Listing all would sprawl the package. Cap: 3 grouped
by `(standard_id, control_ref, edge_type)`, tail `…and N more
related controls.` Auditors can drill from the SPA if they need
the full attribution graph; the package stays scannable.

**4. Verbatim excerpts stay from document_findings.**
Not up for discussion — auditors need the tenant's actual source
text. SSoT stores facts about coverage, not the coverage evidence
itself.

## Codified lessons

### 19. Hybrid reads > single-source purity

Prior arcs (60'.b/e) treated SSoT as the destination for all
per-MUST reads. Ship 61'.a hybridizes: SSoT for state, raw
`document_findings` for evidence text. The rule isn't "read
everything from SSoT" — it's "read *state* from SSoT because
that's what SSoT models." Evidence text is not state; it's
content, and content stays where it was authored.

Rule: when adopting an SSoT layer, don't push data that isn't
"state" through it. Facts about the world (satisfied / stale /
bridged) are state. The world itself (excerpts, filenames,
uploaded documents) is not.

### 20. Attribution as a positive signal, not a hedge

Pre-Ship-60' the bridge coverage layer existed as internal data
with no tenant-facing rendering. Ship 60' surfaced it across five
surfaces. Ship 61'.a puts it on the auditor-facing artifact — the
most conservative surface — and confirms the pattern: attribution
is not a hedge, it's a *positive signal* ("your ISO work already
addresses this GDPR obligation") the tenant can act on. The
alternative framing ("bridged coverage doesn't count for GDPR
compliance") is technically correct but auditor-hostile —
attribution + engine-strict `.satisfied` on the top-level verdict
lets both narratives coexist.

Rule: when a data layer's semantics are "supporting but not
sufficient," surface it *positively* alongside strict compliance
truth. Don't hide it because it complicates the message.

## What's now different in the product

- **Evidence Package respects tenant scope.** N/A-excluded MUSTs
  drop from the required-elements list.
- **Coverage counts match the rest of the product.** Whatever the
  chat / dashboard says about A.5.15 coverage, the Evidence Package
  agrees.
- **Cross-framework attribution reaches auditors.** The
  highest-stakes tenant surface finally shows bridge coverage the
  same way the rest of the product does.

## Follow-ons deferred

- **Bridge source excerpts** — instead of just "Covered via A.5.15
  IMPLEMENTS", pull the excerpt for the source MUST too so the
  auditor sees the actual ISO evidence text. Doable but sprawls
  the package; needs product call on how deep to go.
- **Recommended-additions SSoT parity** — SSoT doesn't track
  SHOULDs. If we ever add SHOULD verdicts to the SSoT writer, Ship
  61'.b-ish would migrate the recommended-additions section too.
