# Ship 77'.a — consensus vs critic-verifier revisit (scoping)

Opens Ship 77'. Follow-on to the parking-lot item (Task #629)
user surfaced during Ship 76' priming.

## Audit findings

Extraction pipeline in `rag/intake/extractor.py` has two mutually-
exclusive LLM-adjacent paths gated by `USE_CONSENSUS_EXTRACTION`
env flag:

| Flag state | What runs |
|-----------|-----------|
| `USE_CONSENSUS_EXTRACTION=1` | `_extract_via_consensus` REPLACES fingerprint + critic-verifier + LLM entirely (extractor.py:289, returns at :291) |
| Not set (default) | `_extract_via_fingerprints` + `_run_critic_verifier_pass` + optional LLM fallback |

**They never coexist in one execution.** The "how are they working
together?" question turns out to have a simple answer: they
aren't. They're competitors chosen at flag-read time.

**Where the duplication lives (code, not runtime):**

- Both compute the SAME fingerprint matches. Consensus's
  `fingerprint_keyword` signal calls the same
  `_fingerprint_extract_matches()` as standalone
  `_extract_via_fingerprints`.
- Both use LLM for a verify/arbitrate step (consensus arbiter for
  borderline zone; critic-verifier for the LLM refiner pass).
- Both apply content-shape + semantic-fit gates.
- ~1250 LOC in `rag/intake/consensus_extraction/` (Ship 33) +
  ~600 LOC in `rag/intake/critic_verifier.py` (Ship 11'.d) — one
  of the two is unused per install (default OFF means critic
  runs everywhere except the flagged-ON Arion demo).

**Signal reuse table** (which signals each path uses):

| Signal | Standalone fingerprint | Critic-verifier | Consensus |
|--------|:-:|:-:|:-:|
| Fingerprint matches | ✓ | ✓ (priming input) | ✓ (signal #1) |
| Explicit refs | ✗ | ✓ (priming input) | ✓ (signal #2) |
| Semantic control-level (Chroma) | ✗ | ✓ (extend pool, 100 controls) | ✗ |
| Semantic MUST-level (Chroma) | ✗ | ✗ | ✓ (must_semantic_topk) |
| BM25 lexical | ✗ | ✗ | ✓ (bm25_topk) |
| LLM verify/arbitrate | ✗ | ✓ (refiner) | ✓ (borderline arbiter) |
| Content-shape gate | ✓ | ✓ | ✓ |
| Semantic-fit gate | ✗ | ✓ | ✓ |
| Grounding check | ✗ | ✓ | ✗ (relies on fingerprint excerpt) |

## User's direction

Rather than pick a consolidation from first-order code analysis
(where each path has trade-offs), Ship 77' takes **first-
principles ground-truth approach**:

1. Manually extract each of the 5 Ship 32/36 baseline docs
   (DPIA, RoPA, Consent, Processor Ops, Data Quality Accuracy),
   producing an expected-verdict list per doc.
2. Rerun consensus (flag ON) on all 5.
3. Rerun critic-verifier (flag OFF) on all 5.
4. Compare each path against the ground truth: precision,
   recall, evidence quality.
5. Decide direction based on evidence, not architectural
   preference.

Ground truth authoring: I draft first-pass extractions, user
reviews + corrects. First doc: DPIA (highest procedural
complexity + broad MUST scope).

## Success criteria for 77'.e decision

The compare should answer:

1. **Recall on ground truth**: what % of expected findings did
   each path emit?
2. **Precision**: what % of emitted findings match a ground-
   truth entry?
3. **Evidence quality**: for correctly-emitted findings, is the
   quote acceptable to an auditor? (Subjective — user-scored.)
4. **False positive characterization**: for spurious findings,
   what class? (Fingerprint over-fire? LLM hallucination?
   Content-shape leak?)
5. **Latency + cost**: LLM tokens burned per doc per path
   (from `ai_call_log`).

Decision rule (proposed): if one path clearly dominates (>15%
recall gap OR clearly better precision AND lower cost), retire
the other. If they trade off (one better recall, other better
precision), refactor toward the union. If they're equivalent,
retire consensus (simpler pipeline, less LOC).

## What's parked

Ship 77' is scoped to the 5-doc measurement. Broader questions
deferred:

- **Should consensus become default even if it dominates on
  5 docs?** — 5 docs is small; production tenants have hundreds.
  Ship 77'.e's decision might be "consensus wins on these 5;
  measure on 20+ before flipping default."
- **What if BOTH paths miss ground-truth items?** — indicates a
  catalog or fingerprint gap independent of extractor choice.
  Track separately as curator arcs.
