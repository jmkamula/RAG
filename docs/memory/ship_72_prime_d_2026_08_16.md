# Ship 72'.d — Snapshot tests + metric consolidation

## What shipped

### `tests/test_finding_contract.py` — 11-case snapshot suite

Locks the extractor-side SSoT against regression in three places:

**Predicate-level (5 tests)**:
- `is_scaffolding` recognizes 25+ reader-reconstructed scaffolding
  shapes (▽/△ rails, `*Do not edit — system id*`, `*Standard text:*`,
  `_Why:_`, `_Good enough:_`, `__✓ Good__`, `__Best practice__`, ☑/☐
  guidance bullets, `[Not applicable...]` callout, prereq category
  headers, `<<TEXT>>` placeholders, `<!-- EDIT-ZONE-START -->`
  comments, `<!-- prefilled from N -->` provenance, horizontal
  rules, `<!-- TABLE-COLUMNS -->` metadata).
- `is_scaffolding` rejects real tenant-authored prose (locks the
  false-positive risk).
- `catalog_recognises` accepts known-good ids, rejects mangled +
  wrong-case ids.

**Contract-level (4 tests)**:
- `bind()` rejects empty text → `EMPTY_TEXT`
- `bind()` rejects scaffolding text → `PURE_SCAFFOLDING`
- `bind()` rejects mangled item_id → `MANGLED_ITEM_ID`
- `bind()` accepts valid candidate → returns `DocumentFinding`
  with resolved control_ref + standard_id.

**End-to-end round-trip (2 tests)**:
- Unedited docx → 0 findings across 4 leaves (A.5.15, A.5.1,
  A.5.24, 6.1.2). This is the exact bug Task #606 dogfood
  surfaced.
- Filled docx (2 placeholders) → 2 correct findings bound to the
  right MUST ids, 0 false positives on unfilled zones.

Any regression in the renderer, reader, or contract will fail one
of these — the 3-way pin means we can't silently drift.

### Metric consolidation onto contract-native counters

`FindingContract.bind()` gained an optional `metrics: dict` param.
When passed, the contract bumps a `contract_skip_<reason>` counter
per rejection reason (`contract_skip_empty_text`,
`contract_skip_pure_scaffolding`, `contract_skip_mangled_item_id`,
`contract_skip_unresolvable_control_ref`).

Every extractor site (6 call sites — 2 templated markdown, 2 xlsx,
1 legacy full-section, 1 LLM parser) now passes
`metrics=doc.extraction_metrics`. The counters land on
`doc.extraction_metrics` alongside the pre-existing per-path
counters (kept backward-compat for
`intake_trace_log` schema stability).

Verified live: A.5.15 unedited round-trip on A.5.15 produces:
```
metrics = {
  contract_skip_empty_text: 6,       # ← new, contract-native
  templated_edit_zones_total: 6,
  templated_edit_zones_bound: 0,
  templated_zones_scaffolding: 6,    # ← pre-existing, backward-compat
  templated_zones_mangled: 0,
}
```

`intake_trace_log` telemetry now sees the contract counters
automatically — no extra plumbing needed. Adding a new
`SkipReason` value in the future automatically becomes a new
counter (via `f"contract_skip_{reason.value}"`).

## Codified lesson

### 45. Test the SSoT, not just the consumers

The old scattered private rules were tested (or not) at each call
site. When we consolidated onto the FindingContract SSoT, the
right test surface is the CONTRACT ITSELF — not each extractor's
integration test. `tests/test_finding_contract.py` pins the
predicate behavior directly + adds two integration snapshots for
end-to-end coverage. Total: 11 cases lock the entire SSoT.

Adding a new scaffolding pattern? One-file change in the predicate
+ one line in the snapshot test's `shapes` list. Adding a new
`SkipReason`? One enum value + one metric counter (via
`_METRIC_KEY_PREFIX` interpolation) automatically. The SSoT +
its tests are the leverage point, not the consumers.
