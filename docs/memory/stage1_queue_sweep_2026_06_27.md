## The non-Neo4j bug

I initially diagnosed a "Neo4j drift": 145 ChecklistItems in Neo4j
that weren't in the Python catalog. That diagnosis was based on a
hand-rolled scan using `dir(drm)` + `isinstance(EvidenceRequirement)`
which missed nested `DerivedSpec.direct_evidence` leaves. The
loader's canonical union (line 471 of `load_to_neo4j.py`) reads:

```python
valid_ev_ids = {r.id for r in ALL_EVIDENCE_REQUIREMENTS} \
             | {req.id for ds in ALL_DERIVED_SPECS for req in ds.direct_evidence}
```

Re-running the catalog count with this union: 4278 = Neo4j. Perfectly
in sync. The orphan-sweep logic in the loader is working correctly;
it just hasn't NEEDED to run since Phase B because nothing was
actually stale.

## Process improvements

- `/tmp/queue_sweep.py` is **not** trustworthy as-is. If reused,
  fix the catalog scan to use the loader's union (see code snippet
  in [[feedback-validate-set-membership]]).
- The xfw_proposer regeneration step IS useful regardless — it
  cleared and refreshed pending bridges deterministically. Worth
  running periodically after large catalog refactors.
- Pre-action diff check: report `python_catalog_count vs neo4j_count`
  before any sweep. Mismatch = stop and investigate.
