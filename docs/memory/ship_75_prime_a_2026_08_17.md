# Ship 75'.a — deterministic-path FindingContract audit + design

Opens Ship 75'. Ship 72'.a made `FINDING_CONTRACT.bind()` the SSoT
for the LLM extraction path but the deterministic extractors —
consensus / critic-verifier / fingerprint — still construct
`DocumentFinding` directly. Same shape of bug that Ship 74' closed
for observability (silent-drop through unforwarded metrics) exists
here as a design gap: any future SkipReason added to the contract
protects the LLM path only.

Ship 75'.a is scoping: audit each deterministic path's current
emission shape, identify friction, propose the sub-arc breakdown.

## Current wiring (Ship 72'.a landmark)

LLM + templated paths route through the contract at 6 call sites
in `rag/intake/extractor.py`:

| Line | Function | Path |
|------|----------|------|
| 909  | `_extract_templated_xlsx` | xlsx column loop |
| 933  | `_extract_templated_xlsx` | xlsx doc_field loop |
| 1112 | `_extract_templated_table_zone` | table column loop |
| 1158 | `_extract_templated_via_edit_zones` | edit-zone loop |
| 1220 | `_extract_templated_via_full_section` | section loop |
| 2626 | `_extract_llm_findings_from_chunk` | LLM output loop |

Each call constructs `ExtractedCandidate(item_id, excerpt_text, …)`
and hands it to `FINDING_CONTRACT.bind()`. The contract's 4
SkipReason values (`EMPTY_TEXT`, `PURE_SCAFFOLDING`,
`MANGLED_ITEM_ID`, `UNRESOLVABLE_REF`) protect these 6 sites.

## Design decisions

### Decision 1 — bind() runs AFTER the deterministic gates

The critic-verifier's grounding / semantic-fit / content-shape
gates and the fingerprint's specificity threshold are extractor-
specific gates, not contract-worthy invariants. They protect the
extractor from emitting noise; they aren't universal skip-reasons.

Keep them in place, upstream of the `.bind()` call. The contract's
scaffolding + mangled + unresolvable checks are additive safety
net, not replacements.

### Decision 2 — no new SkipReason values in this arc

The audit found no reason to grow the SkipReason enum. All 3
paths trust their upstream signals for scaffolding + ref
resolution; the contract's existing 4 reasons still cover the
adversarial-input class (empty text, pure scaffolding, mangled
item_id, unresolvable ref).

If a future arc surfaces a new class (e.g. semantic-fit-below-
threshold as a first-class skip), that arc adds the SkipReason;
Ship 75' inherits the current shape.

### Decision 3 — consensus + fingerprint share extraction_path values

Both currently emit `inference_source="fingerprint_match"` — good,
their evidence originates from fingerprint matches. Keep that as-is.
The `extraction_path` differs ("consensus" vs "fingerprint") and
should stay differentiated: consensus is the LLM-arbitrated path,
fingerprint is deterministic-only.

### Decision 4 — migrate one path at a time, verify each

Ship 74'.b caught a real pre-existing bug on first run. Each
migration in 75' should be a separate sub-arc with its own dogfood
+ eval, not a batch commit. If the contract rejects candidates the
old path accepted (or vice-versa), we want to see it per-path.

| Sub | Scope | Complexity |
|-----|-------|------------|
| 75'.a | This audit + design | (this doc) |
| 75'.b | Migrate fingerprint path | Simplest. Direct wire — construct `ExtractedCandidate` from the match metadata, replace `findings.append(DocumentFinding(…))` with `contract.bind(candidate)`. | 75'.c | Migrate consensus path | Similar to fingerprint but wired inside `_extract_via_consensus`. Verify no verdicts silently disappear (they shouldn't — no skip conditions match the consensus shape). |
| 75'.d | Migrate critic-verifier path | Requires plumbing derived `standard_id` upstream so the candidate carries it at construction. Gate-then-bind order preserved. Dogfood: critic-heavy doc (large multi-section policy). |

Each sub-arc's dogfood must verify the `contract_skip_*` counters
(Ship 74'.a-d columns) populate correctly on the deterministic
path — that's the observability proof the migration produced
uniform SSoT behavior.

## Risks + mitigations

**Risk 1** — Old path accepts, contract rejects. E.g. a fingerprint
match on legitimate scaffolding text (rare — fingerprint gate is
usually tight). Mitigation: dogfood per sub-arc verifies count
parity; discrepancy triggers a design conversation, not a merge.

**Risk 2** — Contract rejects a candidate that had a valid
downstream consumer (e.g. posture writer). Mitigation: bind()
returns a `BindResult`, not a raw None — the caller can decide
whether to log-and-drop or fall back. This arc drops (matches
current behavior of the LLM path).

**Risk 3** — Deterministic path metrics diverge from LLM path
metrics because upstream gates emit different `contract_skip_*`
distributions. That's expected + honest signal, not a bug.
Documented in each sub-arc's dogfood.
