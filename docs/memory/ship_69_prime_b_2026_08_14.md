# Ship 69'.b — Retarget bridge edges to named sub-clauses

## What shipped

Ship 69'.a's audit found 50 bridge edges (11.1%) whose rationales
named a specific sub-clause the target framework already has as
a node (`Art.32.1.b`, `Art.5.1.f`, `Art.28.3.a`, …). Ship 69'.b
edits `enrichment/relationships/relationship_catalog.py` to point
each of those 50 edges at the narrower target — a data-only
change, zero schema migrations.

50 for 50 requested retargets applied. Neo4j reload showed 452
managed bridge edges preserved (same count, narrower targets)
and 50 old whole-article edges pruned via the loader's
declarative orphan sweep. Re-running Ship 69'.a's audit against
the retargeted catalog reports **retargetable_now = 0** — the
retargeting is idempotent and complete.

## The two follow-on bugs Ship 69'.b uncovered

Retargeting alone would have broken Evidence Package rendering
because:

**Bug 1 — parent-article EPs lost sub-clause bridges.** The
`req:Art.32:program_review` leaf queries
`read_must_verdicts_by_control(control_ref='Art.32')`. Ship 59'.e's
strict `AND target_control_ref = ANY(%s)` filter (self-contained
sub-clause attribution) meant Art.32 whole-article verdicts saw
only bridges with `target_control_ref='Art.32'` — none of the
retargeted A.5.18 → Art.32.1.b, A.5.24 → Art.32.1.d, etc.

Fix: `rag/posture/must_verdicts.py::read_must_verdicts` widens
the bridge lookup to `target_control_ref = ANY(%s) OR
target_control_ref LIKE ANY(%s)` where LIKE patterns are
`{ref}.%`. Whole-article callers now roll up descendant
sub-clause bridges. Sub-clause callers still get exact-match
semantics (their LIKE `Art.32.1.b.%` matches nothing deeper).

**Bug 2 — mapping-meta fetch used the wrong Neo4j target id.**
The EP's Ship 68'.b batch fetch built `target_id =
f"{leaf.standard_id}:{leaf.control_ref}"` (i.e. `GDPR:2016/679:Art.32`)
for the rationale + confidence lookup. But the retargeted edges
now point at `GDPR:2016/679:Art.32.1.b`. The Cypher query returned
nothing → rationale + confidence disappeared from the ↗ blocks
even though the source control still surfaced.

Fix: `BridgeSource` dataclass carries a new `target_control_ref`
field populated from `posture_must_bridge_coverage.target_control_ref`.
The EP `mapping_meta` fetch keys `(source_std, source_ref,
edge_type) → set[target_control_ref]` and looks up each edge at
its actual retargeted target.

## Codified lesson

### 35. Data model changes ripple through readers designed for the OLD topology

Ship 59'.e's *self-contained sub-clause attribution* was correct
for the topology at the time (bridges targeted whole articles).
Ship 69'.b makes bridges point at sub-clauses AND the same
reader now needs a parent-article union to preserve UX. The
reader wasn't wrong — it was pinned to an assumption that broke
when the graph shape moved.

Rule: when you change graph edge granularity, walk every reader
that queries the affected edge type. The change isn't done
until each caller either intentionally opts into the new
granularity or gets a compatibility union.
