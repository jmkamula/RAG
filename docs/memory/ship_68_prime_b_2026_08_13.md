# Ship 68'.b — Coverage-language retire + asserted-mapping reframe

## The lie the product was telling

Ships 60–62 built numeric coverage UX on top of `posture_must_
bridge_coverage`. Ship 68'.a's dogfood investigation surfaced that
the underlying data model doesn't support the claim: bridge edges
in Neo4j are curator-authored assertions at *whole-source-control →
whole-target-control* granularity, not per-MUST-pair semantic
mappings. Ship 59'.b's writer cross-products every satisfied source
MUST × every target MUST, so:

- Ship 60'.j's `(N/M MUSTs bridge-covered)` suffix = trivially
  `(target.n_total − target.n_satisfied)`. Looked measured, wasn't.
- Ship 60'.g's SPA chip *"N elements already covered by evidence for
  related ISO 27001:2022 controls"* = same story.
- Ship 61/62's `↗ Covered via A.5.18 IMPLEMENTS` = same story, plus
  showed a source excerpt that had no guaranteed semantic fit with
  the target MUST.

The user's question — *"how have we covered the areas of Art.32 that
are partially covered by A.5.18?"* — exposed the wider problem: the
current UX pretends measurement where the data model only carries
assertion.

## The reframe

**Every claim of "coverage" is retired. Each surface now shows three
independent facts + one epistemic disclaimer:**

1. **Which mapping was asserted** (curator catalog: source control,
   edge type, confidence).
2. **The curator's verbatim rationale** (already populated on 100%
   of 452 bridge edges).
3. **The source control's own posture + progress** (independent
   fact from the tenant's SSoT — no conflation with target).
4. **Epistemic disclaimer**: *"Mapping is an ArionComply catalog
   assertion; auditor-defensibility depends on evidence specificity
   and mapping acceptance."*

The reader composes the story. No fake coverage number. No implied
validation.

## Surfaces reframed this ship

- **`rag/casefile/digest.py::_render_xfw_bridges`** — retired
  Ship 60'.j's `(N/M MUSTs bridge-covered)` suffix. Line reads
  `- Art.32 ← A.5.15 [Comply], A.5.18 [NC]` (no fake count).
- **`static/arioncomply.html::renderBridgeChip`** — the SPA chip
  used by the case-file card leaf checklist + the dashboard drill-in
  reframed from *"N elements already covered by evidence for related
  X controls"* to *"Related X controls are asserted (per ArionComply
  catalog) to implement one or more of these missing elements.
  Auditor-defensibility depends on the specific evidence and
  mapping acceptance."*
- **`rag/posture/evidence_package.py`** — Evidence Package's
  cross-framework header + per-element `↗ Covered via` block
  reframed to *"asserted implementation via related controls"*
  with rationale + confidence + source posture. Batch-fetches
  rationale + confidence from Neo4j edge properties (already 100%
  populated) and source posture from `posture_controls` +
  `posture_must_verdicts`. Reader sees WHY the mapping was
  asserted, not a fake number.

Test file `tests/test_evidence_package.py` updated to lock the new
phrasing (5 of 5 assertions rewritten; snapshot tests all pass).

## Codified lesson

### 33. Retire the lie before optimizing the truth

Ships 60–62 built infrastructure (SSoT, bridge writer, precompute
patterns, reader migrations) around a coverage narrative the data
model couldn't support. The temptation on discovering this was to
build MORE infrastructure (scope_items authoring on 452 edges, sub-
clause refactor) to *make* the narrative true. Ship 68'.b did the
cheaper honest thing first: stop telling the lie. The infrastructure
remains available (68'.a scope_items schema stays dormant) for when
the specific 1-1 pair mapping is genuinely honest; the broader
sub-clause refactor moves to 69'.a audit.

Rule: when UX makes a claim the data doesn't support, retire the
claim before trying to strengthen the data. Text changes ship in
hours; data-model changes ship in weeks. And the honest text
change eliminates the reason to build the bigger change on the
critical path.
