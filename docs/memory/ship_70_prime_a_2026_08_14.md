# Ship 70'.a — Prefer sub-clause targets in ↗ block ranking

## Motivation

Ship 69's arc dogfood ([[ship-69-arc-ux-dogfood-2026-08-14]])
surfaced a specific friction:

> The Ship 69'.d retargets are buried. B.8.3.1 → Art.28.3.e
> (a Ship 69'.d retarget that names the narrower sub-clause
> the curator intended) sits at position 5 — inside the
> "12 more" bucket. The whole-to-whole edges (A.7.2.6 →
> Art.28.3, A.5.19 → Art.28) rank higher because they carry
> more satisfied source MUSTs. **This is a real ranking
> bug**: the arc's precision work is hidden behind the arc's
> coarser predecessors.

The bridge writer's cross-product model gives whole-article
edges more satisfied source MUSTs (they inherit every one of
their MUSTs as bridge targets). The pre-arc ranker sorted
by that count. Ship 69's sub-clause retargets — precisely
what the auditor wants to see first — ranked last.

## The change

`rag/posture/evidence_package.py::_render_bridged_leaf` (the
`- ↗` block loop) changes its sort key from:

```python
sorted(grouped.items(), key=lambda kv: -len(kv[1]))
```

to:

```python
sorted(
    grouped.items(),
    key=lambda kv: (
        -target_ref_by_group.get(kv[0], "").count("."),
        -len(kv[1]),
    ),
)
```

Target granularity = number of `.` segments in the target
ref (`Art.28.3.e` = 3, `Art.28.3` = 2, `Art.28` = 1).
Sub-clauses rank first; satisfied MUSTs are the tiebreaker
within a granularity tier.

`target_ref_by_group` is a parallel dict populated in the
grouping pass — first BridgeSource's `target_control_ref`
wins, safe under the Ship 69'.b invariant that a Neo4j
edge (source, edge_type) tuple has exactly one target
per catalog row.

## Verified on Arion

Same MUST as the dogfood sample (`item:Art.28:confidentiality`
under `req:Art.28:data_processing_agreement`):

**Before Ship 70'.a**:
```
↳ A.7.2.6 → Art.28.3    (n=14)
↳ A.5.19  → Art.28      (n=9)
↳ A.5.20  → Art.28      (n=8)
…and 12 more asserted mappings.
```

**After Ship 70'.a**:
```
↳ B.8.2.1 → Art.28.3.f  (n=7,  granularity=3)
↳ B.8.3.1 → Art.28.3.e  (n=6,  granularity=3)   ← Ship 69'.d retarget
↳ B.8.4.2 → Art.28.3.g  (n=4,  granularity=3)
…and 12 more asserted mappings.
```

Auditor sees three sub-clause-specific rationales up front.
The whole-paragraph + whole-article bridges are still available
in the "12 more" bucket.

## Design tradeoff

**Chosen**: strict granularity-first ordering. Auditor precision
beats source-coverage volume.

**Alternative considered**: weighted score (granularity × 0.5 +
n_satisfied × ...). Rejected because a very-well-satisfied
whole-paragraph bridge could still outrank a barely-populated
sub-clause, hiding the arc's precision work again.

The "…and N more" bucket is the safety valve: broader
attributions aren't lost, just relegated. Ship 71'-style
expandable UX makes them accessible.

## Codified lesson

### 37. Rankers age with topology

Ship 59'.b's cross-product bridge writer + sort-by-n_satisfied
was correct when every bridge was whole-to-whole. Ship 69'
introduced granularity variance; the ranker's assumption
(coarser = more satisfied MUSTs = more important) broke.
Follow-up: the ranker didn't need to know about granularity
until the graph made granularity meaningful.

Rule: rankers embed assumptions about the ranked domain.
When you change the domain shape (edge granularity, node
depth, attribution model), audit the rankers. They fail
silently — the "top 3" still renders, just with the wrong
three.

Cf. lesson 35 (data model changes ripple through readers
designed for the OLD topology). Same shape; different site.
Reader = fetches data; ranker = orders data. Both age with
topology.

## Follow-ons

- **Ship 71' — expandable "N more" UX**. Currently `…and N
  more` is a black hole in markdown. HTML surface + JSON
  API would let the auditor click through. Larger arc,
  needs SPA work.
- **Ship 72'-ish — confidence weighting?** Some sub-clause
  retargets sit at `confidence: HIGH`; ranking could also
  push HIGH-confidence sources up. Would need a curator pass
  to widen confidence-tag coverage (many pre-Ship-69 edges
  default to no role).
