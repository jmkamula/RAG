# Ship 72'.a — FindingContract + is_scaffolding + templated paths migrated

## Arc opener

Ship 72' takes the SSoT-for-extractor-rules approach we should have
used weeks ago instead of patching a series of narrow scaffolding
checks. Dogfood on Task #606 surfaced a pre-existing bug that made
any unedited docx round-trip produce ~39 false `Comply` findings per
4 leaves, and the reflexive fix would have been "extend
`_is_pure_scaffolding` in the templated path." That's the exact
scope-narrowing move Codified Lesson 44 warns against.

Instead, Ship 72' consolidates the extractor-side rules — what makes
a candidate excerpt into a valid `DocumentFinding` — into ONE
canonical layer. Every extractor path (templated, LLM, workbook,
xlsx) will consume it. Adding a new scaffolding pattern is a
one-file edit. Adding a new extractor path doesn't need to know the
rules — it just emits candidates and lets the contract decide.

72'.a is the arc opener: introduces the module + migrates the two
templated paths.

## What shipped

### `rag/intake/finding_contract.py` (new, ~250 LOC)

Canonical extractor-side SSoT:

- **`is_scaffolding(text) -> bool`** — app-wide predicate. Sequentially
  strips every scaffolding shape our renderers can emit
  (placeholders, prefill provenance comments, reader-reconstructed
  patterns: `*Do not edit — system id*`, `*Standard text:*`, `_Why:_`,
  `_Good enough:_`, `__✓ Good__`, `__Best practice__`, `☑`/`☐`
  guidance bullets, ▽/△ rails, horizontal rules, `[Not applicable...]`,
  prereq category headers). If nothing substantive remains, the
  input is scaffolding.
- **`catalog_recognises(item_id) -> bool`** — Task #606's membership
  check promoted from `extractor.py` into the contract. Same
  5,385-id set from `ALL_EVIDENCE_REQUIREMENTS ∪ DerivedSpec.direct_evidence`.
- **`ExtractedCandidate` dataclass** — what extractors emit.
- **`SkipReason` enum** — `OK` / `EMPTY_TEXT` / `PURE_SCAFFOLDING` /
  `MANGLED_ITEM_ID` / `UNRESOLVABLE_REF`. Makes rejections observable.
- **`FindingContract.bind(candidate)`** — the gate. Runs every check,
  emits either a `DocumentFinding` or a `BindResult(reason)`. Logs
  anomalies (MANGLED / UNRESOLVABLE) at WARN, expected drops (EMPTY /
  PURE_SCAFFOLDING) at DEBUG.
- **`FINDING_CONTRACT` singleton** — module-level default caller.

### `rag/intake/extractor.py` — 2 paths migrated

`_extract_templated_via_edit_zones` and `_extract_templated_via_table`
now emit `ExtractedCandidate` objects through `FindingContract.bind()`.
The ~35 LOC of ad-hoc `_is_pure_scaffolding` + `_catalog_recognises` +
`item_control_ref` + `_control_ref_to_standard` + `DocumentFinding`
construction per path becomes a single 8-line block. Metrics
(`templated_zones_scaffolding` etc.) preserved for backward-compat;
Ship 72'.d will consolidate onto the contract-native
`skip_reason` counters.

### `rag/intake/readers.py` — reader zone-boundary fix

Root cause of the false-Comply bug: `_arion_docx_to_edit_zones`
opened the edit zone at each `◆ Required element — <slug>` label and
closed it at the next `◆` / heading / `---`. That captured the ENTIRE
gap — guidance body, `✓ Good:` examples, `Best practice` bullets,
placeholder line — into the reader-emitted `<!-- EDIT-ZONE-START -->`
block. Extractor saw non-empty text and bound everything.

Fix: when the docx has Task-#604 rails (`▽ Enter your evidence for X ▽`
/ `△ End of X △`), use them as the zone boundary. The `<<MUST>>`
marker still emits at the ◆ label for round-trip binding, but the
`<!-- EDIT-ZONE-START -->` waits for the ▽ rail. Pre-72' behavior
kept intact as fallback for docs authored outside our render.

Also fixed: `_ARION_CLICK_PLACEHOLDER_RE` didn't match mammoth's
`*\\[ Click to enter your evidence here \\]*` (italic-wrapped
escaped brackets). Updated regex tolerates the wrapping — empty
placeholders now strip correctly, so the reader-emitted zone
contains nothing.

## Codified lesson

### 44. Domain rules at the highest layer, not the call site

Deferred from the Ship 72' arc opener conversation. When a bug
surfaces at one call site, the temptation is to patch that site's
local check. That's a scope-narrowing move dressed as expedience.
If the underlying concept ("what is scaffolding?", "what is a
valid marker?", "what is tenant evidence?") is genuinely shared
across the app, codify the rule at the highest layer where it's
meaningful — one predicate, one canonical set, used everywhere.

Applies to Ship 72' (this arc) and retroactively to Task #606
(should have consolidated `_catalog_recognises` across every
extractor rather than only touching `_extract_templated_via_edit_zones`
and `_extract_templated_via_table`).

Same pattern as Ship 60' (Advisory refactor via SSoT + bridge
awareness): consolidate scattered private rules into one canonical
source, then migrate consumers one at a time. Ship 60' did it for
posture STATE (downstream of extractor). Ship 72' does it for
finding VALIDITY (upstream of extractor).
