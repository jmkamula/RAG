## Intake false-positive classes closed

Surfaced on Arion's Technical Consulting Privacy Procedure re-extract:
5 known false-positives all suppressed. Each has a rule now.

**1. Header-block fingerprints** — `_find_header_block_end` scans
first 2000 chars for contiguous "Key: value" metadata lines (Owner:,
Version:, Effective Date:, Classification:, Approved by:) and
excludes that region from fingerprint scanning. Fixed A.5.9:
owner_per_asset false-positive that matched "Owner" in every
policy header.

**2. Footer-block fingerprints** — `_find_footer_block_start` scans
last 2000 chars for trailing metadata block (Last Reviewed:,
Next Review Date:). Same _HEADER_BLOCK_KEYS vocabulary via shared
`_is_metadata_key_line` predicate. Fixed A.6.6:last_reviewed and
A.5.36:review_date.

**3. LLM metadata-block extraction** — `_looks_like_metadata_block`
post-processing filter in `_parse_llm_response`. When the LLM
emits an evidence quote where every non-empty line is a Key:value
metadata line, drop the finding. Covers the LLM path even if
header suppression above fails. Fixed A.5.37 "Documented Operating
Procedures" false-positive.

**4. xfw_bridge weak-source inheritance** — `propose_for_findings`
now picks the LONGEST substantive source per (control_ref,
standard_id) rather than take-first-in-iteration. Fixed cases
where a header-only fingerprint hit competed with a substantive
LLM extract on the same source control — bridge previously took
the header-only excerpt.

**5. 27701 explicit-ref recognition** — `extract_refs_from_text`
now has an `ISO27701` branch that recognizes A.7.x.y and B.8.x.y
patterns with A→7 / B→8 pairing enforced. Bogus `A.8.2.3` (legacy
27002:2013) refs are rejected. Extractor unions explicit_refs
into scoped candidates + augments target_leaves so LLM sees the
MUSTs to bind against.

**6. Controller/processor mapping asymmetry** — 5 27701 A-side
mappings lacked `[controller, X]` short-fallback that their B-side
pairs had (`[processor, X]`). Fixed: A.7.2.8, A.7.4.6, A.7.5.1,
A.7.5.2, A.7.5.4. Made Records-of-Processing-Activities.docx land
on A.7.2.8 (Controller RoPA) — previously it only hit B.8.2.6.

## Depth-vs-breadth insight

Multiple approvals didn't flip more controls despite reinforcing
per-MUST density. Engine promotion NC → OFI requires **at least one
leaf FULLY satisfied** (all its MUSTs bound). Broad multi-leaf
coverage with partial evidence doesn't count. Retention procedure
doc got 6 findings on A.7.4.5 but only cleared 1 leaf's worth of
MUSTs — the *procedure* leaf. Companion artefacts (register +
review + scope statement) needed to promote the control.

Depth-over-breadth heuristic: tenants get more posture flips per
doc when the doc TIGHTLY covers a single control's leaves rather
than broadly touching many controls.
