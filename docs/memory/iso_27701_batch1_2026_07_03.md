## The two new workflow scripts

Because ISO 27701 is copyrighted, we can't check the source JSON
(equivalent to `iso_nodes_phase1.json` / `gdpr_nodes_phase2.json`)
into the repo. This forced two new curation-workflow scripts:

- `scripts/seed_27701_requirement_nodes.py` — hardcodes the 14
  RequirementNode shells (id, standard_id, ref, title,
  obligation_text, node_type, applies_to, business_description)
  from §7.2/§8.2 standard text. Idempotent MERGE by id. Extend the
  `BATCH1_SEEDS` list per curation batch.
- `scripts/index_27701_to_chroma.py` — reads 27701 RequirementNodes
  from Neo4j (source of truth after seed script runs) and upserts
  into `COL_27701` + `COL_ALL` collections without touching ISO/GDPR.

**Pattern for future copyrighted-standard onboarding** (TISAX / VDA /
SOC 2 / etc.):
  1. Extend `KNOWN_STANDARD_IDS` in `relationship_catalog.py`
  2. Extend `_STANDARD_LABEL_MAP` / `_STANDARD_DISPLAY` /
     `humanizeStandardId` (already in place for 27701 from the
     provisioning pre-work — [[iso-27701-phase01-2026-07-03]])
  3. Add a `scripts/seed_{standard}_requirement_nodes.py` per batch
  4. Add a `COL_{STANDARD}` constant in `vector/indexer.py` +
     `search_{standard}` helper in `vector/retriever.py`
  5. Add a `scripts/index_{standard}_to_chroma.py` for partial
     refresh
  6. Author EvidenceRequirements in `document_requirements.py`
  7. Author bridges in `relationship_catalog.py`
  8. Seed posture rows for Arion (SQL)
